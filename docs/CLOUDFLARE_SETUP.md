## Постоянное хранилище заявок D1

[Подтверждено] Заявка сначала записывается в D1 с AES-256-GCM шифрованием контактов и ответов. Telegram и email получают уведомления после записи. Состояние доставки хранится отдельно для каждого канала. Никакие персональные данные не передаются в открытые логи или параметры URL.

[Подтверждено] В `wrangler.jsonc` закреплена существующая база `deniz-estate-leads`, binding `DB`, ID `7a35b81d-dc12-42a0-9582-fd804580da27` из панели владельца. Код хранилища использует `env.DB`. Создавать вторую базу не требуется.

[Подтверждено] Схема таблиц находится в `migrations/0001_leads.sql`. После входа Wrangler примените её командой `npx wrangler d1 migrations apply deniz-estate-leads --remote`. Для локальной проверки используйте `--local`. Таблицы и индексы создаются с IF NOT EXISTS, без удаления имеющихся данных.

[Подтверждено] `keep_vars: true` сохраняет переменные, заданные в панели, кроме явно указанного `LEADS_ENABLED=true`. Секреты не задаются в конфигурации и не перезаписываются деплоем. Основной Custom Domain сохранён в панели; маршрут www закреплён в конфигурации.

## Секреты и получатели

[Подтверждено] Значения настраиваются в Cloudflare Workers → Settings → Variables and Secrets. Ключи шифрования, Telegram и Resend хранятся как Secrets; список получателей и отправитель могут быть переменными панели или Secrets. Их нельзя писать в HTML, клиентский JavaScript, GitHub Issues или исходники.

| Имя | Значение |
| --- | --- |
| `LEAD_ENCRYPTION_KEY` | Случайный ключ из 64 шестнадцатеричных символов, 32 байта |
| `TELEGRAM_BOT_TOKEN` | Токен созданного через BotFather бота |
| `TELEGRAM_CHAT_ID` | ID личного чата или закрытой группы для заявок |
| `RESEND_API_KEY` | Ключ Resend с разрешением отправки писем |
| `LEAD_EMAIL_FROM` | Отправитель с домена, подтверждённого в Resend |
| `LEAD_NOTIFICATION_EMAILS` | Один или несколько email получателей через запятую |

[Подтверждено] Ключ шифрования можно сгенерировать локально: `openssl rand -hex 32`. Сохраните его в менеджере паролей. Потеря ключа делает старые заявки недоступными; замена ключа без переноса данных не поддерживается. Для локальных секретов скопируйте `.dev.vars.example` в `.dev.vars`; последний игнорируется Git.

[Подтверждено] Перед отправкой в личный Telegram-чат пользователь должен открыть бота и нажать Start. Для группы добавьте бота в выбранную закрытую группу и используйте её chat_id. Отправка уведомлений и связь с самим клиентом — разные действия: бот уведомляет менеджера, а менеджер связывается с клиентом выбранным в квизе способом.

[Подтверждено] В Resend нужно подтвердить домен отправителя и указать фактических получателей в `LEAD_NOTIFICATION_EMAILS` через запятую. Код проверяет все адреса, убирает пробелы и повторы, затем передаёт массив получателей одним запросом Resend. Невалидный адрес отклоняет весь список; частичной отправки по ошибочной конфигурации нет. Поддерживается до 50 уникальных адресов. Отправитель читается из `LEAD_EMAIL_FROM`, ключ — из `RESEND_API_KEY`; значения не зашиваются в код. DNS-записи берутся только из панели Resend; текущие MX, SPF и DKIM домена нельзя заменять произвольными шаблонами.

## Включение и проверка

1. После настройки D1, ключа шифрования и обоих каналов изменить `LEADS_ENABLED` в `wrangler.jsonc` на `"true"`, закоммитить и отправить в GitHub.
2. Отправить отдельную тестовую заявку с явно тестовым именем. Проверить уведомление в выбранном Telegram-чате и письмо на согласованном адресе.
3. Проверить, что повторный запрос не создаёт вторую запись, а сбой одного канала не теряет заявку. Фоновый Cron запускает повторные попытки каждые 5 минут, обрабатывая до 5 записей за запуск.
4. Подключить реальный домен; добавить `SITE_URL=https://ваш-домен` как **build variable** Cloudflare. Для preview-сборок переменную не задавать. После повторной сборки проверить canonical, sitemap, HTTPS и отсутствие noindex на основной публикации.

[Подтверждено] При недоступности Telegram/Resend или ошибке их настроек заявка, принятая при LEADS_ENABLED=true, остаётся зашифрованной в D1, успешный канал повторно не отправляется. Сбойные отправки повторяются с увеличением интервала до часа. Защита email от повторов дополнительно использует Resend Idempotency-Key. Telegram не предоставляет такого ключа: в редком случае потери подтверждения возможен повтор уведомления; его можно узнать по одинаковому ID заявки.

[Подтверждено] Для контроля очереди в D1 можно проверить без раскрытия контактов: `SELECT telegram_status, email_status, COUNT(*) FROM leads GROUP BY telegram_status, email_status;`. Автоматические тревоги администратору пока не подключены. Cron удаляет заявки старше 180 дней с даты создания, до 500 за запуск. Миграция 0002 добавляет индекс даты. Копии Telegram и email оператор удаляет отдельно.

[Подтверждено] Оператор по данным владельца — SERGEY VAKORIN; адрес и email опубликованы в юридических разделах. Согласие формы не предустановлено; версия политики 2026-11-03. Cloudflare, Telegram и Resend раскрыты в политике. Базовый Google Ads AW-18527353101 использует Consent Mode v2: до согласия все четыре параметра denied, библиотека загружается только после разрешения маркетинга. Дополнительные согласия не предустановлены; выбор хранится локально до 180 дней и изменяется в футере. GA4 и события конверсии пока не подключены.

## Благодарность и адрес конверсии

[Подтверждено] После аудита 03.11.2026 сборка Workers Builds main автоматически использует https://deniz-estate.property, если SITE_URL отсутствует. Локальная/preview-сборка по умолчанию noindex. SITE_URL имеет приоритет: не задавайте production-значение для preview. HTTPS и www приводятся к основному адресу в Worker с сохранением пути и параметров; HTTPS POST из старых форм www не перенаправляется.

[Подтверждено] assets.run_worker_first=true обеспечивает единые редиректы и security headers. Все запросы проходят Worker: контролируйте использование бесплатного лимита запросов в панели. Основной Custom Domain, маршрут www и DB сохранены.

[Требует уточнения] Зональные настройки WAF, DNS и Security Events недоступны текущему API-токену. Правовые основания использования бренда, договоры обработки и международные передачи требуют документального подтверждения оператором. Полный отчёт: [SECURITY_ADS_AUDIT.md](SECURITY_ADS_AUDIT.md).

[Подтверждено] После ответа API `success: true` и `leadId` квиз переводит посетителя на `/thank-you`. До ответа показывается индикатор ожидания; ошибка оставляет посетителя на форме. Подтверждение в sessionStorage содержит только ID, язык и время, действует 30 минут. Без него прямой визит возвращает на главную и не загружает Google Ads на странице благодарности. С отключённым sessionStorage благодарность показывается в текущем окне без перехода. Страница исключена из sitemap и имеет noindex.

[Требует уточнения] Конверсия по URL `/thank-you` настраивается отдельно в рекламном аккаунте. Данная правка не создаёт действие конверсии в Google Ads и не добавляет conversion label.

[Подтверждено] Уведомления Telegram и Resend используют одинаковый текст: заголовок, отдельные дата и время заявки, имя и язык, способ связи и контакт, критерии подбора. Часовой пояс указан рядом с временем вверху; бюджеты перечисляются отдельными строками, остальные ответы идут после двоеточия. Ответы выделены жирным (HTML Telegram и email; для email также есть текстовая версия). Блок согласия не включается в уведомления; само согласие хранится в зашифрованной заявке D1. ID скрыт из текста и темы письма, но сохранён в базе и ключе идемпотентности Resend. Часовой пояс по умолчанию `Asia/Nicosia` (Кипр); его можно изменить переменной Cloudflare `LEAD_NOTIFICATION_TIME_ZONE`.
